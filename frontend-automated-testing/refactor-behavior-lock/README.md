# 特征锁定测试（源码拆分 / 重构期护栏）

## 什么时候用

准备搬移、拆分或重构既有代码，且要求「行为一字不差」时。

## 核心思想

不验证「功能对不对」，只证明「改前改后一模一样」。

## 怎么做

1. **先录后锁**：以当前实现为基准，把代表性输入与边界输入的输出原样记下来当标准答案。
2. **只测外部行为**：喂输入、看输出，不依赖内部写法，内部可自由搬移。
3. **连现状怪癖一并锁定**：现在怎样就锁怎样，不顺手「改好」，防止把差异当改进混进来。
4. **结果确定化**：固定时间与随机源，保证每次结果一致。
5. **输入表覆盖**：正常、空值、越界、异常等场景都要有。
6. **先织网、后搬移**：每拆一块先有网，全绿才算无差别通过。
7. **及时退役**：拆分结束并验证通过后，这类锁定用例应删除，只保留长期契约测试。

## 定位

它是拆分期的**临时护栏**，不是永久资产。它保护「搬」，不保护「改」——业务要变时，报红是应该的，先确认是不是你有意要改，是就更新基准。
